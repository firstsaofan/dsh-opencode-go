# 接口健康

> English version: [health.md](health.md).

OpenCode Go 的接口地址有一个别人都没有的毛病：**它没有变更通告**。

官方文档现在只写按协议细分的地址（`.../inference/go/openai/v1`、`.../inference/go/anthropic/v1`），
而本插件一直使用的扁平根地址 `.../zen/go/v1` 在两者之外继续正常应答。两条路径都没有出现在
任何变更日志或邮件里。所以一个部署只能在"所有对话都开始失败"的那一刻，才知道地址被换了。

这个页面说明插件怎么提前发现这件事。

## 本 fork 默认开启，以及为什么这是一个偏离

upstream 把 `healthCheck` 默认设为 `off`，理由是成立的：一个版本不应该改变现有部署的行为。
本 fork 把它默认设为 `both`，这是一个有意为之的偏离。

理由就是本页开头那一条。默认关闭的探针对"接口静默变更"这件事没有任何保护作用——它只保护那些
已经知道要去查的人，而那恰恰是不需要它的那批人。开启的代价是每六小时三个请求，且没有一个能生成内容。

有两件事让这个默认值是安全的，而不是噪音：

- **没有密钥就不抱怨。** 还没存密钥的部署每条线路都会收到 `401`，那是探针要的"线路存活"答案，不是故障。
  这个发现照样记录，但不会 warn。一个每六小时重复一次、永远重复的 warn，就是一个不再被阅读的 warn。
- **全部开销就是三个请求。** 永远不生成任何 completion，所以一轮检查对套餐的 token 额度零消耗。

想拿回 upstream 的行为就设 `healthCheck: off`。以后 rebase 回 upstream 时，
要带走的就是这一行——记录这个决定的测试是 `tests/suites/config.test.mjs` 里的
`endpoint health is on by default in this fork`。

## 核心思路：用拒绝换答案

探针不生成任何内容，只发一个**必然被拒绝**的请求，然后读状态码：

| 请求 | 回答 | 含义 |
|---|---|---|
| POST `{root}/chat/completions`，body 是一个空对话 | `400` | 这条线路还在。健康的样子就是一次拒绝 |
| 同上 | `404` | 这条线路没了 |
| 同上 | `401` | 线路还在，是密钥的问题 |
| 没有回答 | — | DNS、TLS、连接被拒或超时 |

这个区分就是全部的信号来源，也是探针不花钱的原因：请求体带的是空对话，三个 API 都会在校验阶段
拒绝，任何一个模型都不会开始运行。输出上限同时写成 1，这样即使某个网关宽容地接受了空对话，也不会
产出任何实质内容。

探针发的**请求头和真实调用逐字节一致**，包括 `x-opencode-session`。这不是细节：如果头部不一样，
探针就永远看不到"网关开始要求这个头"这类变化——而那正是最需要被提前发现的一种。

## 状态与信号

一次回答被归成一个 `state` 和一个 `signal`。分类是纯函数（`lib/health/classify.js`），优先级
从"地址没了"向外排，因为这些状态并不等价等重：

| `state` | 什么时候 | 该做什么 |
|---|---|---|
| `alive` | 线路应答了 | 什么都不用做 |
| `degraded` | 线路应答了，但有条件需要人处理 | 看 `signal`：`AUTH_REFUSED` 去查密钥，`QUOTA_EXHAUSTED` 额度用完了，`SESSION_HEADER_REQUIRED` 网关改了契约，`PROTOCOL_REJECTED` 这个模型不在这条协议上，`SERVER_ERROR` 服务端不健康 |
| `moved` | `404`/`405`/`410` | 地址变了；看 `suggestion` |
| `unreachable` | 完全没有回答 | 网络或主机的问题 |

`signal` 有八个，都列在 `lib/health/classify.js` 的 `SIGNAL` 里。两条规则值得单独说：

- **body 里的标记优先于伴随它的状态码。** 一个写着 `MissingSessionID` 的 `400`，天真地读就是
  "请求有问题"，而实际上网关是在要一个头。
- **`ModelProtocolUnsupported` 既不算地址变了，也不算故障。** 网关要回答"这个模型不走这个协议"，
  必须先解析到路由**和**模型——这是"线路还在"能拿到的最强证据。它会作为独立信号报出来，
  因为知道一条线路不服务哪些模型本身有价值，但它既不会让一轮降级，也不会 warn。
  这一条是实况跑出来的，不是测试跑出来的：探针拿一个只走 chat 的模型去打三条线路，
  于是每轮都有两条线路回答"不支持"，而且永远如此。所以探针会为每条线路挑一个它**真的服务**的模型
  ——目录里若有三种协议都能走的模型就优先用它——这样健康时的回答仍然是一次普通的校验拒绝。

## 什么时候检查

三个触发，从便宜到灵敏：

| 触发 | 请求数 | 说明 |
|---|---|---|
| **真实流量失败** | 3 | 最高价值。一个看起来像"地址没了"而不是"请求错了"的拒绝（`404`/`405`，或正文提到找不到路由）会立刻触发一次全量检查——**断的那一刻就响**，而不是几小时后 |
| **定时** | 3 | 默认每 6 小时一次，与 `modelsCacheSeconds` 对齐 |
| **手动** | 3 | 页面上「立即检查」，或 `POST /opencode-go/health-check` |

**请求级的拒绝不会触发检查。** 上下文超限、额度用完、模型 id 拼错——调用方已经拿到足够的信息了，
再查一遍只是噪音。

## 频率：阶梯、退避、熔断

接口变更是天/周尺度的事件，分钟级轮询没有意义，还会在服务已经不舒服的时候继续打扰它。

| 机制 | 行为 |
|---|---|
| 正常间隔 | 6 小时（`healthIntervalSeconds`） |
| 退避阶梯 | 30 秒 → 2 分 → 10 分 → 1 小时 → 放弃。迁移从来不是一个干净的瞬间，它是一个"有的线路答、有的不答"的窗口；阶梯能抓住一次网络抖动，也不会把一次长故障变成每小时一次的闹钟 |
| 熔断 | 连续 3 轮 `moved`/`unreachable` 后停掉定时检查。地址不在的时候，定时探测纯属浪费——只剩流量触发 |
| **恢复** | 任意一轮 `alive` 会清零计数和熔断。所以地址修好之后不用重启就会被发现 |

`degraded` **不走阶梯**，仍然按正常间隔检查：密钥被拒绝、网关要新头部，这些是关于**这个部署**的
事实，要由人去改，等是没用的。

## 会给出"改用什么"

发现地址变了以后，探针会去试 `healthCandidates` 里的候选根地址，然后给出可以直接粘贴的建议：

```json
{
  "code": "BASE_URL_MOVED",
  "detail": "https://opencode.ai/zen/go/v1 no longer serves /messages",
  "note": "This adapter resolves one baseURL per route, so a layout that serves different protocols from different roots needs one route per root.",
  "routes": [
    { "protocol": "anthropic", "path": "/messages", "baseURL": "https://opencode.ai/inference/go/anthropic/v1" }
  ]
}
```

两条规则让这条建议值得相信：

- **只有当每个丢失的协议都找到了去处，才会给建议。** 部分应答会产生一份看起来合理、然后在没人测过的
  模型上失败的配置——那比什么都不说更糟，因为读者会照着改，然后失去"它没work"这个证据。
- **`note` 永远带着**，因为那是没有探针能替读者解决的部分：这条路由只有一个 `baseURL`，而一个按不同
  根地址分发协议的布局需要每根地址一条路由。

候选地址只在**已经出事之后**才去试。地址正常时，候选的答案只是同一份好消息的第二份拷贝。

## 明确不做的事

- **不发任何能生成内容的请求。** 探针永远不花钱。
- **不写出密钥。** 落盘的文件里只有主机名、状态码和信号名。
- **不接管调用。** 探针的发现是挂在失败上的诊断，不是一次可能成功而真实请求却失败的替代重试。
- **不改写行为。** 一轮 `alive` 就是 `alive`；探针从不改变路由该怎么工作。

## 落盘

每一轮写一个文件，和模型缓存、用量文件放在一起：

```
~/.dsh/cache/opencode-go-health.json
```

里面是上一轮的完整结果加最近 20 轮的简史（`checkedAt` / `state` / `signals`）。重启后历史还在，
页面不会是一片空白。写不进去只是一条警告，不会让一轮检查失败。

## 页面

设置页在「连接」下面多一节「接口健康」，和它报告的对象挨着：

- 没开检查时，说明怎么开（`healthCheck: scheduled` 或 `both`）
- 没检查过时，明说"还没有检查过"，而不是显示成正常
- 显示状态、上次检查时间、`signal` 列表
- 地址变了就把建议显示出来
- 「立即检查」是这张页面上唯一一个由按钮触发的请求

`GET /opencode-go/health` 只从内存作答，打开页面不花任何请求；`POST /opencode-go/health-check`
才真的跑一轮。
